## Implemented surfaces

- The identity-access public seam validates Google OIDC signature, issuer, audience, time, verified-email, nonce, state, and CSRF evidence before an Account or Session transaction begins.
- The versioned `r1-v1` fixed adapter supplies synthetic development and test identities and rejects staging or production construction with `FIXED_IDENTITY_FORBIDDEN`.
- Kysely and PostgreSQL own Accounts, one-to-one Google identity links, hashed bearer credentials, Docket Session limits, expiry, revocation, and reconstructable `AccountCreated`, `SessionCreated`, and `SessionRevoked` audit facts.
- Fastify routes issue short-lived authentication challenges and `Secure`, `HttpOnly`, `SameSite=Lax`, `__Host-` Session cookies. Authentication responses and account projections omit bearer tokens and stable provider subjects.
- React routes use the generated TypeScript client through a same-origin server proxy for Google and fixed authentication plus live Account Session management. The screens cover provider states, device, approximate location, last activity, class, current-device marker, and one/all termination controls.
- The PostgreSQL adapter serializes issuer and subject as a namespaced JSON tuple before deriving its transaction-scoped advisory-lock key. The representation is deterministic, preserves tuple boundaries, and contains no PostgreSQL-invalid NUL delimiter.

## PostgreSQL regression evidence

The first Docker-backed run reached `PostgresIdentityTransaction.lockIdentity` and failed because its text parameter embedded a NUL separator, which PostgreSQL rejected as `invalid byte sequence for encoding "UTF8": 0x00`; the concurrent enrollment test consequently admitted zero Sessions. The minimized single-test command reproduced that exact failure. After replacing the separator with the namespaced tuple encoding, the same test passed, the focused encoding invariant passed, and the full four-test integration suite passed.
