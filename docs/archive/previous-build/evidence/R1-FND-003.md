## Declared outputs and interfaces

- `@docket/database` exports the `MigrationPlan`, `MigrationResult`, migration schemas, stable migration errors, plan loader, and runner while keeping filesystem and PostgreSQL details behind the package interface.
- Every package with migration authority declares its table-name prefixes in its own immutable `migrations/owner.json`; the loader produces one contiguous global sequence and rejects undeclared or foreign targets.
- Migration metadata records ownership, release and adjacent-release compatibility, change kind, affected tables and constraints, forward assumptions, transformation and retention impact, forward-fix guidance, and a read-only verification query.
- `platform_migration_journal` permanently records checksummed `MigrationApplied` event data. PostgreSQL rejects update and delete attempts through an append-only trigger.
- `@docket/testkit` exports `TestDatabase`, an asynchronously disposable PostgreSQL 17.11 Testcontainers harness that executes the production migration seam.
- `@docket/migrate-app` provides the release-time `pnpm migrate` entry point; `pnpm migration:check` validates the checked-in plan without connecting to a database.
