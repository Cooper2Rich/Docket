## Scope

This record covers Active Role Context, current server-side authority resolution, privileged-context session limits, recent Google reauthentication, per-tab role switching, and context-scoped cache destruction for `R1-AUTH-001`, `R1-PRIV-001`, and `R1-CONS-001`.

## Implemented surfaces

- The identity-access public seam owns runtime-validated Authority Grants, Active Role Contexts, Authority Decisions, reauthentication evidence, grant synchronization and invalidation, role entry and exit, and current protected-action resolution.
- PostgreSQL migration 4 owns `identity_authority_grants`, `identity_role_contexts`, and `identity_reauthentication_events`, backfills each existing Account's inherent Account-holder grant, constrains event completeness and chronology, and prevents more than one active context for a Session and tab.
- Authority resolution uses exactly the selected grant and exact resource scope. It never combines roles or permissions, exits stale contexts durably before returning `CONTEXT_STALE`, returns generic denials without resource existence disclosure, and destroys every active context when a grant is invalidated.
- A privileged role activates 30-minute inactivity and 12-hour absolute Session limits and revokes any other active privileged Session for that Account. Sensitive policies require identity-matched reauthentication no older than ten minutes.
- Fastify exposes role-context state, entry, exit, and Google/fixed reauthentication routes. Every browser request carries a stable tab-local identifier through the same-origin proxy.
- The reusable role header persistently identifies exact role and scope, distinguishes privileged context without color alone, blocks switches while local work is unresolved, clears context-scoped browser cache before a switch, supports native keyboard operation, and offers immediate privileged-session termination.
