## Strict-review finding closure

1. **Atomic Manager succession:** Identity now grants a role-neutral School scope selector and never carries `school.membership.manage`; `schools_memberships` is the sole mutable Manager authority. Every Manager mutation rechecks the current School Manager inside the School transaction. Transfer acceptance changes the prior and successor Memberships, School version, `SchoolManagerChanged` event, and command receipt in one transaction. Injected late-failure rollback and PostgreSQL concurrent-transfer tests prove no split authority and exactly one active Manager.
2. **Durable events:** TypeBox contracts and persisted records cover `SchoolCreated`, `SchoolVerified`, `SchoolMembershipGranted`, and `SchoolManagerChanged` with producer, allowed consumers, aggregate/version, actor, time, causation, correlation, idempotency, privacy, retention, and payload fields. In-memory rollback and PostgreSQL transaction tests prove event and authority state commit or roll back together.
3. **Client-stable idempotency:** all applicable mutations use actor, command, and stable key with a canonical SHA-256 input hash. Advisory locks serialize PostgreSQL retries; identical concurrent/replayed requests return the stored result, conflicting key reuse returns `IDEMPOTENCY_CONFLICT`, and replay never reissues an offer bearer token.
4. **Authorization and audiences:** executable vectors cover Platform administrator creation/verification, current Manager mutation and restricted projection, ordinary School staff projection, exact Account recipient inbox/acceptance, audit-consumer event allowance, and generic foreign-School/non-member denial. School staff never receive pending offers unless they are the current Manager.
5. **Duplicate and inference negatives:** tests reject normalized canonical/alias collisions across provisional and verified boundaries. Same-domain Accounts cannot discover, list, accept, or operate on another Account's offer; errors do not expose School existence or domain-derived membership.
6. **Promised web flows:** the new Platform School administration route supplies labeled native creation and verification forms with required field validation and explicit loading, empty, denial, success, and error states. Existing Manager and recipient routes remain connected to the generated client.
7. **Keyboard and WCAG evidence:** tests focus and activate native create, verify, issue, transfer, revoke, and exact-recipient acceptance controls by keyboard, alongside axe checks using WCAG 2 A/AA, 2.1 AA, and 2.2 AA tags.
8. **Public-interface encapsulation:** the Schools root export no longer exposes in-memory stores, internal records, transactions, clocks, or factories. Production consumers use the package root; only the explicitly checked `contract-source` tooling export is allowed, and boundary tests reject relative cross-package and all other package-subpath imports.
